01 它解决什么

RWA 上链的真正门槛不在「发币」，而在合规：谁能持有、能转给谁、如何处置违规地址、收益如何分配——这些规则必须写进代币本身并可被审计。本 Skill 把这套合规发行流程封装为一个 Agent 可端到端执行的工具包：发行前以只读尽调建立可验证的风险评级，发行时由 ERC-3643 风格的身份与转账约束保证合规，发行后将该资产沉淀为可复用的能力单元。

02 端到端流水线 尽调 → 发行 → 复用
STEP 01

链上尽调闸门

对发行方与托管地址执行只读链上分析，输出带 evidence 的 GREEN / YELLOW / RED 评级。未通过即拒绝后续一切发行操作。

STEP 02

合规 RWA 发行

部署 CompliantRWAToken，统一治理投资者准入、受限转账、份额增发与销毁、冻结与恢复，以及链上派息。

STEP 03

资产 Skill 输出

发行完成后自动生成 skills/<SYMBOL>-asset/，固化合约地址与操作指令，成为可被其他 Agent 调用的能力单元。

03 合约架构与合规闸门 单合约内聚 · 命名对齐 ERC-3643

身份注册模块 IdentityRegistry

  • 准入registerIdentity / batchRegisterIdentity / removeIdentity
  • 查询isVerified / investorCountry

合规模块 ModularCompliance

  • 规则canTransfer / setComplianceRules
  • 约束持有人上限、单人额度上限、holderCount

生命周期模块

  • 份额mint / burn / forcedTransfer
  • 风控地址冻结、部分冻结、钱包恢复、全局 pause

派息模块

  • 分配depositDividend / claimDividend / dividendOf
  • 模型累计每股派息，免遍历持有人、gas 安全

每一笔转移都经由 _update() 钩子的三层检查；mint 与 forcedTransfer 为监管场景仅校验身份层，绕过合规层全局规则但仍要求收款方已验证。

04 核心能力

合规与准入

  • 双重转账检查isVerified + canTransfer 同时通过方可转移
  • 投资者准入单个与批量身份注册，按国别记录
  • 转账前预检只读校验合规结果，规避无效交易与 gas 浪费
  • 规则治理持有人上限、单人额度上限链上可配

资产生命周期

  • 份额管理mint / burn / forcedTransfer
  • 风控操作地址冻结、部分份额冻结、全局 pause
  • 钱包恢复recoveryAddress 支持合规场景资产迁移
  • 收益分配累计每股派息模型，gas 安全且免遍历持有人
